# Перенос BOMJob и TitleJob

## Общая часть

В корневом репозитории остаются launcher.c, собранный EXE, Python API, инструменты
подключения, тесты, CI и документация. В конечном плагине — бизнес-код, настройки,
шаблоны, копия EXE под его именем и папка .adapter с общей библиотекой.

Зависимость фиксируется на commit. Сборка плагина подтягивает корневой репозиторий
через vendor_adapter.py; конечному пользователю Git и компилятор не нужны.
Для автоматического получения будущих версий обновляется commit в сборке плагина,
а не запускается git pull при открытии DipTrace.

## BOMJob 0.2.7

1. Создать отдельную тестовую папку плагина через new_plugin.py --mode job.
2. Перенести туда бизнес-файлы BOMJob: bomjob*.py, bom_core.py, bom_output.py,
   bom_page_labels.py, diptrace_environment.py, inspect_xml.py, bomjob.ini и templates.
3. В plugin.py положить examples/bomjob_bridge/plugin.py из этого репозитория.
4. settings.xml должен содержать ExpMode=All и ImpMode=None.
5. Новый adapter.ini управляет общей оболочкой; старый EXE/его launcher больше не нужен.

Рабочая BOM уже проверена через эту обёртку на Linux с настоящим XML захвата и OTS:
один ODS в Docs, исходный XML не изменён. Сами пользовательские XML/OTS в этот
публичный репозиторий не включены. Нативный запуск в DipTrace пока требует проверки.

## TitleJob

Для переноса нужна текущая рабочая версия TitleJobUI.zip с её Python и адаптером.
При подготовке этого репозитория загрузка архива завершилась HTTP 502, поэтому
замена рабочего TitleJob не выполнялась.

Целевая замена транспорта:

- точка входа main(ctx);
- исходные данные через ctx.read_xml()/document();
- переменные через ctx.environment(список_имён);
- обработчики Apply меняют полную копию XML и вызывают ctx.commit_xml(...);
- закрытие/Cancel без Apply ничего не публикует;
- исключение после commit отменяет публикацию;
- настройки mode=ui, write_scope=sheet_settings;
- settings.xml: ExpMode=All, ImpMode=All.

Пример examples/ui показывает только принцип: поиск Designed by по первой строке
и замена следующих строк. Полный редактор VPT, две вкладки и сохранение правил
должны остаться бизнес-кодом TitleJob. Общая библиотека не создаёт проектные
переменные DipTrace и не выдаёт изменения окружения процесса за сохранение проекта.
